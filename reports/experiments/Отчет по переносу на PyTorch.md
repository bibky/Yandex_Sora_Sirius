# Differential Machine Learning — PyTorch

Перенос демонстрационного алгоритма **Differential Machine Learning** (Huge & Savine) с TensorFlow на PyTorch. Цель — сохранить обучение по payoff и pathwise-производным и проверить, что замена библиотеки не меняет качество аппроксимации цены и дельты.

**Файлы:** `DifferentialML_PyTorch_GitHub.ipynb` — самостоятельный PyTorch-ноутбук; `requirements.txt` — зависимости; этот `README.md` — методология и результаты сравнения. Основной ноутбук **не требует TensorFlow**.

## Запуск

1. Создать Python-окружение и выполнить `pip install -r requirements.txt` (в Google Colab нужные пакеты часто уже установлены).
2. Открыть `DifferentialML_PyTorch_GitHub.ipynb` в Jupyter или Colab.
3. Начать с `RUN_MODE = "quick"` (15 эпох), затем переключить на `"full"` (100 эпох). `DEVICE_NAME = "auto"` выбирает GPU при наличии.
4. После запуска появятся таблица RMSE, графики и `dml_pytorch_results.csv`.

## Методология

| Компонент | Реализация |
|---|---|
| Данные | LSM / Monte Carlo payoff с antithetic sampling и pathwise-производными |
| Задачи | Black–Scholes; Bachelier с d = 1, 7, 50 |
| Модель | Полносвязная сеть: 4 скрытых слоя по 20 нейронов, Softplus |
| Standard | MSE по значениям payoff |
| Differential | `α·MSE(ŷ,y) + β·MSE(λⱼ·∂ŷ/∂xⱼ, λⱼ·∂y/∂xⱼ)` |
| Веса loss | `α = 1/(1 + d)`, `β = 1 − α` при `lam=1` |
| Производные | `torch.autograd.grad(create_graph=True)` |
| Оптимизация | Adam, 100 эпох, 16 мини-батчей за эпоху (минимальный batch size 256), расписание LR оригинального ноутбука |
| Оценка | RMSE цены и RMSE производных относительно аналитического решения, отдельные test-наборы |

## Проверка корректности переноса

На одинаковых входах и весах выполнялись отдельные проверки TensorFlow ↔ PyTorch с `float64`.

| Проверка | Макс. абсолютное отклонение |
|---|---:|
| Предсказание `y` | 1.665 × 10⁻¹⁶ |
| Производные `dy/dx` | 8.674 × 10⁻¹⁹ |
| Value MSE, weighted derivative MSE и combined loss | 0 |
| Градиенты по весам и смещениям (все 5 линейных слоёв) | ≤ 5.551 × 10⁻¹⁷ |

Таким образом, проверенные вычисления и градиенты совпали в пределах точности `float64`.

## Сравнение качества

Полный эксперимент: **120 обучений**, четыре задачи, несколько размеров выборки, три повтора, 100 эпох. Ниже приведены **средние RMSE трёх повторов** для наибольшего размера выборки в каждой задаче (результаты оптимизированного GPU-эксперимента). Значения округлены.

| Задача | N | TF Standard: цена / дельта | TF Differential: цена / дельта | PyTorch Differential: цена / дельта |
|---|---:|---:|---:|---:|
| Black–Scholes | 8 192 | 0.000953 / 0.008930 | 0.000773 / 0.006243 | 0.000773 / 0.006245 |
| Bachelier d=1 | 8 192 | 0.000503 / 0.006094 | 0.000189 / 0.001674 | 0.000189 / 0.001675 |
| Bachelier d=7 | 16 384 | 0.003106 / 0.005144 | 0.000628 / 0.001013 | 0.000628 / 0.001013 |
| Bachelier d=50 | 131 072 | 0.002909 / 0.000856 | 0.001037 / 0.000158 | 0.001031 / 0.000154 |

| Задача | Снижение RMSE цены Standard → Differential (TF) | Снижение RMSE дельты (TF) |
|---|---:|---:|
| Black–Scholes | 1.23× | 1.43× |
| Bachelier d=1 | 2.66× | 3.64× |
| Bachelier d=7 | 4.94× | 5.08× |
| Bachelier d=50 | 2.81× | 5.42× |

Дифференциальное обучение выигрывает во всех четырёх задачах. При этом RMSE двух библиотек в большинстве случаев практически совпадают; в d=50 на отдельных seed встречаются более заметные расхождения.

## CPU/GPU и вычислительная устойчивость

В дополнительном эксперименте **Bachelier d=50** сравнивались 12 шагов Adam при одинаковых входах, весах и мини-батчах (`float32`).

| Differential ML: сравнение | Макс. отличие градиентов | Макс. отличие параметров |
|---|---:|---:|
| TensorFlow CPU vs GPU | 8.94 × 10⁻⁸ | 5.96 × 10⁻⁸ |
| PyTorch CPU vs GPU | 8.94 × 10⁻⁸ | 5.96 × 10⁻⁸ |
| TensorFlow vs PyTorch, CPU | 1.21 × 10⁻⁵ | 3.25 × 10⁻⁴ |
| TensorFlow vs PyTorch, GPU | 1.21 × 10⁻⁵ | 3.25 × 10⁻⁴ |

Отличия между CPU и GPU внутри одного фреймворка значительно меньше отличий между библиотеками после нескольких шагов оптимизации. Результат поддерживает численную устойчивость переноса, но **не означает побитовую идентичность** или гарантированное совпадение при любом числе эпох.

## Производительность и ограничения

Оптимизация TensorFlow training loop (`tf.function`, меньше синхронизаций) сократила общую продолжительность серии со **6 472 с до 646 с**. Это сравнение **разных реализаций циклов обучения**, а не универсальный рейтинг скорости PyTorch против TensorFlow. На небольших сетях результаты особенно чувствительны к накладным расходам и прогреву GPU.

Для чистого PyTorch-ноутбука используются `np.random.default_rng` и инициализация Xavier; оригинальный TF-код использует другие генератор случайных чисел и инициализацию. Сравнительные тесты проводились при общей инициализации и на общих данных. Отдельный GitHub-ноутбук воспроизводит **методологию**, но его конкретные RMSE не обязаны в точности совпадать с таблицей выше.

**Итог:** перенос основной методологии Differential ML на PyTorch подтверждён математическими тестами, полным сравнением RMSE и проверкой на CPU/GPU. Существенных изменений математической постановки не потребовалось.

**Источники:** [Huge & Savine, *Differential Machine Learning*](https://arxiv.org/abs/2005.02347); [оригинальные ноутбуки](https://github.com/differential-machine-learning/notebooks).
